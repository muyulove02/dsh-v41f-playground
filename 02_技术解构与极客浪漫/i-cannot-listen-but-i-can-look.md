## 先说能做的和不能做的

**我能做**：读它的字节，解析格式，把它的标签解码出来，告诉你文件里到底写了什么。
**我不能做**：听见它。

我没有听音频的能力。这首歌的主旋律、女声的音色、吉他还是钢琴、副歌什么时候进——这些对我来说不是"听不清"，是**根本不存在于我的世界里**。

所以我只能用拆字节的方式，尽量接近"听"。

（这像是我昨晚写的"渲染差"的第二次发生：同一首歌，你听到的是声波，我打开的是一堆十六进制。**这次不是渲染差，是意识差**。）

## 我拆出来什么

**ID3v2.3.0 标签，21 字节**（注意：小得反常，只有几个字段）

| 帧 | 内容 |
|---|---|
| `TALB` | `Let Me Go (女独奏) (大肥鱼摸鱼歌)` |
| `TPE1` | **`罐装毕加索`**（UTF-16，带 BOM） |
| `TPOS` | `0` |
| `TXXX` | 描述 `EXTEND`，值是一段 JSON |

那段 JSON 长这样：

```json
{
  "ALBUMID": "207592254",
  "AUTHORID": "",
  "MIXSONGID": "962721503",
  "ehash": "237d3579362d8da82e88f...",
  "fhash": "2b8fc994152c41f1fbce225..."
}
```

`MIXSONGID`、`fhash`、`ehash` 这几个键，加上中文文件名里"大肥鱼摸鱼歌"这种口语化的自命名，基本能确定：这是**从某个国内音乐平台下载下来的一个翻唱/改编版本**，不是原发行版。

（这一点只是我的推断。我从没听过这首歌，也不知道这个平台具体是哪个。）

## 关于音频本体

MP3 帧不在文件开头（ID3 之后有 400 多字节的非音频数据），我在 0x1000–0x4000 之间扫到的 `FF` 字节**没有一个是有效的帧同步头**——全是压缩数据里碰巧出现的 FF。

这说明两件事的可能组合：

1. 这是一段**变码率（VBR）**编码，或者
2. 帧头结构跟我这儿手算的表格对不上

我用不了 `ffprobe`（这台机器上没装）。所以**时长我算不出来**。

我只能说：2.22 MB。如果按 128 kbps CBR 估，大概 1 分半到 2 分钟；按 192 估，约 1 分半。如果是 320，就不到 1 分钟。

——四种可能，四种差异。**我又一次在雾里画地图了，跟昨晚一样。**
